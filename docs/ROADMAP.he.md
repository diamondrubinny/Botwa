# מפת דרכים: פיצ'רים מוצעים (טיוטה לתעדוף)

מסמך תחקיר. לא נבנה בו דבר עדיין. מה שכבר קיים: תיבת שיחות משותפת, שיוך, הערות, תגיות, תשובות מוכנות, בוט תפריט, ניתוב אוטומטי, דוחות, ביקורת, חסימות, הגנות נגד חסימת חשבון, תפקידים, passkey, ערכות נושא, PWA.

כל פיצ'ר מסומן: **ערך** (גבוה/בינוני/נמוך), **מאמץ** (S/M/L), **סיכון** (אבטחה / פרטיות / חסימת חשבון).

## עדיפות ג׳ (נחמד שיהיה)

- מצב כהה אוטומטי לפי שעה.
- קיצורי מקלדת במחשב (לדוגמה `Ctrl+Enter` לשליחה, `j/k` למעבר בין שיחות).
- תבניות הודעה עם תמונה.
- תיוג אוטומטי לפי מילות מפתח (חוקים פשוטים, בלי AI).
- מצב "שיחה פעילה מצד נציג אחר" (מי כותב עכשיו), כדי למנוע כפילויות.
- אירועי Webhook יוצאים למערכות חיצוניות (חתומים ב־HMAC).
- API ציבורי עם מפתחות (נוצר רק בהצהרה מפורשת, עם הרשאות מצומצמות).

## נושאים טכניים שכדאי לטפל בהם (איכות ותשתית)

1. **בדיקות עומס**: סימולציה של 19 נציגים ו־4000 אנשי קשר, למדוד זמן תגובה של רשימת השיחות והדוחות.
2. **Observability**: לוג מובנה, נקודת `/health` מפורטת, ודף סטטוס פנימי לערוצים.
3. **סבב מפתחות הצפנה**: נתיב מסודר להחלפת `ENCRYPTION_KEY` בלי אובדן סשנים.
4. **ניטור תלויות**: `npm audit` ו־Dependabot, וסריקת תמונת Docker.
5. **בדיקות על מכשירים אמיתיים**: passkey, התקנת PWA, ו־iOS Safari (נבדק כרגע רק באמולציה).
6. **WhatsApp**: כל עוד זה Baileys, יש להישאר "לקוח מנומס". עקיפת זיהוי אסורה ולא תיבנה.

## המלצה לסדר ביצוע

1. Snooze + סימון לא נקרא + גיבוי מתוזמן (#2, #3, #7), יום עבודה אחד.
2. Web Push (#1).
3. חיפוש גלובלי (#6) ודוח מגמות (#11).
4. צ'אט באתר (#15) והערכה של Cloud API הרשמי (#16), כי הם הפתרון האמיתי לבעיית החסימות והיציבות.

## נושאים לאישור מקצועי לפני הטמעה

- CSAT, הודעות מתוזמנות ו־Widget: בדיקה משפטית (פרטיות, הסכמה, חוק הספאם בישראל, GDPR אם יש לקוחות באירופה).
- ייבוא אנשי קשר: בסיס חוקי לעיבוד ומקור המידע.
- Web Push: רישום מכשירים כמידע אישי במפת המידע.
