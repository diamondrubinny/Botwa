# חומת אש ואנטי-וירוס

ההגנה בנויה בשלוש שכבות. **שום שכבה לא מבטיחה אבטחה מוחלטת.** לפני ייצור מומלץ שבודק חדירות יבדוק את המערכת.

## 1. האנטי-וירוס (בתוך Botwa)
- **מה נסרק:** כל קובץ שמגיע מלקוח נכנס להסגר ונסרק ב-ClamAV (השירות `clamav` ב-docker compose). רק קובץ נקי זמין לצוות, וקובץ נגוע נמחק ונרשם ביומן.
- **עוד דברים שנסרקים:** תמונות פרופיל, תמונות הגלריה, לוגו, קבצי מאגר הידע וקבצי אקסל שמייבאים.
- **סריקה חוזרת (חדש):** כל שעה, קבצים שנבדקו לפני שבוע או יותר נסרקים שוב עם החתימות העדכניות. כך נתפס גם קובץ שהתקבל לפני שהאיום היה מוכר. קובץ שנמצא נגוע נמחק, מסומן, נרשם ביומן, ונשלחת התראה (אם הוגדרו התראות).
- **מסך מצב:** הגדרות ← "אנטי-וירוס" מציג אם הסורק פעיל, את גרסת החתימות ואת הגיל שלהן (אזהרה מעל 3 ימים), כמה קבצים נבדקו השבוע, ומאפשר "סריקה חוזרת עכשיו".

## 2. חומת אש לפאנל (בתוך Botwa)
- **הפעלה:** הגדרות ← "חומת אש לפאנל" ← מסמנים "להגביל" ומכניסים כתובות ורשתות מותרות (למשל רשת המשרד, או ה-VPN). מי שלא ברשימה לא רואה את הפאנל ולא יכול להתחבר.
- **מה נשאר פתוח:** הצ'אט באתר, ה-Webhooks של הערוצים (וואטסאפ רשמי וכו') ובדיקת התקינות. אחרת המערכת הייתה מפסיקה לקבל הודעות.
- **ה-API:** ל-Power Apps ולאינטגרציות יש תיבה נפרדת. שירותי ענן של מיקרוסופט יוצאים מכתובות משתנות, ולכן ברירת המחדל היא לא להגביל אותם (הם מוגנים במפתח).
- **רשימה חסומה:** כתובות שלא מקבלות כלום, גם לא את הצ'אט.
- **הגנה מנעילה עצמית:** אי אפשר לשמור הגדרה שחוסמת את הכתובת שממנה שומרים. ננעלתם בכל זאת? הוסיפו `FIREWALL_DISABLE=true` ל-`/opt/botwa/.env`, הריצו `docker compose up -d`, תקנו את ההגדרה והסירו את השורה.
- **מאחורי proxy (HestiaCP / nginx / Caddy):** צריך `TRUST_PROXY=true` ב-`.env`. אחרת כל הגולשים נראים מכתובת ה-proxy, והמסך יזהיר על כך.

## 3. הגנת השרת עצמו
```bash
cd /opt/botwa && sudo ./scripts/harden.sh --check    # דוח בלבד, בלי שינויים
cd /opt/botwa && sudo ./scripts/harden.sh            # עם אישור לכל שלב
```
הסקריפט בודק ומציע:
- **פורטים חשופים:** מסד נתונים, הסורק ופורט האפליקציה לא אמורים להיות פתוחים לאינטרנט. Docker עוקף את ufw בפורטים שהוא מפרסם, ולכן נבדק גם מה הקונטיינרים מפרסמים.
- **חומת אש:** ufw שחוסם הכול חוץ מ-SSH (בפורט שלכם, עם הגבלת קצב), 80 ו-443. **בשרת HestiaCP הסקריפט לא נוגע ב-ufw**, כי Hestia מנהל את חומת האש בעצמו. מנהלים אותה בפאנל של Hestia ← Server ← Firewall, ומומלץ להגביל את פורט הפאנל של Hestia לכתובות שלכם.
- **fail2ban:** חסימה של ניחושי סיסמה ב-SSH (חמישה כישלונות = שעה חסימה).
- **עדכוני אבטחה אוטומטיים:** unattended-upgrades.
- **SSH:** אזהרה אם מותרות כניסה כ-root או סיסמאות. השינוי עצמו ידני, אחרי שיש משתמש sudo עם מפתח, כדי לא לנעול את עצמכם בחוץ.
- **אנטי-וירוס:** בדיקה שהסורק של Botwa פעיל. `--host-av` מתקין גם ClamAV בשרת עצמו, עם סריקה שבועית של `/opt`, `/home`, `/var/www` ו-`/tmp`. היא רק מדווחת ללוג ולא מוחקת.

הסקריפט לא הורץ על שרת Ubuntu או HestiaCP אמיתי, אלא רק במצב בדיקה בסביבת הפיתוח. מומלץ להריץ קודם `--check`.
