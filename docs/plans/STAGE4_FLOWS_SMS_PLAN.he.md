## חלק א: WhatsApp Flows לטפסים

### 1. מטרה
היום טופס נשלח כקישור: פותחים דף, מקבלים קוד אימות בווצאפ, ממלאים וחותמים. עם Flows, הלקוח ממלא את הטופס **בתוך ווצאפ**, במסכים מקוריים של האפליקציה, בלי לצאת ממנה ובלי קוד אימות. התשובות חוזרות אלינו כהודעה רגילה בשיחה, וממנה נוצר ה-PDF החתום.

### 2. מה גילינו בתיעוד (והשפעה על התכנון)
| עובדה (Meta) | השפעה |
|---|---|
| Flow יכול לעבוד **בלי endpoint** (מסכים קבועים). התשובה מגיעה ב-webhook הרגיל כהודעה מסוג `nfm_reply` עם `response_json` | בלי שרת נוסף, בלי מפתחות RSA ובלי דרישות זמינות של Meta. **נבחר בזה.** |
| הרכיבים: TextInput (text/number/email/phone), TextArea, DatePicker, Dropdown, RadioButtons, CheckboxGroup, **OptIn**, Footer | כל סוגי השדות שלנו נתמכים, **חוץ מחתימה מצוירת** |
| **אין רכיב חתימה** | חתימה = אישור מפורש (OptIn: "אני מאשר/ת וחותם/ת אלקטרונית") ושם מלא מוקלד. ראו שאלה 1 |
| תווית שדה: עד **20 תווים**. טקסט עזר: עד 80 | לכל שדה תהיה "תווית קצרה". המערכת מקצרת אוטומטית, ואפשר לערוך בעורך |
| Flow שפורסם (PUBLISHED) **לא ניתן לשינוי** | גרסת טופס חדשה יוצרת Flow חדש. הישן מסומן DEPRECATED |
| `flow_token`: מזהה שאנחנו קובעים, חוזר בתשובה. ה-Flow ID **לא** חוזר | הטוקן יהיה מזהה אקראי של בקשת הטופס (כמו בקישור היום) |
| בתוך 24 שעות: הודעה אינטראקטיבית מסוג `flow`. מחוץ ל-24 שעות: רק תבנית מאושרת עם כפתור Flow | בתוך השיחה זה עובד מיד. לשליחה קבוצתית צריך תבנית מאושרת |
| גודל Flow JSON: עד 10MB. עד 10 ענפים במודל הניתוב | טפסים ארוכים יחולקו לכמה מסכים |
| תמיכה ב-RTL ובעברית ב-Flows | **דורש אימות** בבדיקה על מכשיר אמיתי (התיעוד לא מתייחס לכך) |

### 3. User Stories
1. כנציג, בשיחה בערוץ הרשמי, אני בוחר "שליחת טופס" ← "בתוך ווצאפ" (במקום קישור). הלקוח מקבל כפתור "מילוי הטופס".
2. כלקוח, אני ממלא שדות במסכי ווצאפ, מאשר את ההצהרה, ומקליד שם מלא כחתימה.
3. התשובה מגיעה לשיחה, נבדקת בשרת, ונוצר PDF נעול עם עמוד ביקורת: "נחתם דרך WhatsApp Flow, מהמספר X, בתאריך Y, מזהה הודעה Z".
4. כמנהל טפסים, אני רואה לכל תבנית את מצב ה-Flow שלה (טיוטה / פורסם / שגיאות אימות של Meta), ותצוגה מקדימה.
5. בשליחה קבוצתית (קיים היום), אפשר לבחור "בתוך ווצאפ", אם יש תבנית מאושרת עם כפתור Flow.

### 4. ארכיטקטורה
- **`forms/flowjson.ts`:** ממיר תבנית טופס ל-Flow JSON.
  - טקסט ← TextInput. מספר, אימייל וטלפון לפי input-type. ת"ז ← TextInput עם pattern.
  - תאריך ← DatePicker. תיבת סימון ← OptIn.
  - חתימה וראשי תיבות ← OptIn להצהרה ו-TextInput לשם מלא.
  - חלוקה למסכים של עד 8 שדות. המסך האחרון: סיכום והצהרה. ה-payload של `complete` כולל רק את מזהי השדות.
- **`channels/whatsapp-cloud.ts`:**
  - `createFlow`, `updateFlowJson` (assets), `publishFlow`, `deprecateFlow`, `getFlow` (status, validation_errors, preview_url).
  - `sendFlow` (interactive type flow).
  - פענוח `nfm_reply` ב-webhook.
- **`forms/service.ts`:** `submitFromFlow(token, response_json, from)`.
  - הבדיקה היא אותה בדיקה של `checkValue` שקיימת היום.
  - ה-PDF נוצר באותו מנוע. החתימה מוצגת כטקסט: "נחתם אלקטרונית: <שם>".
- **מסד נתונים:**
  - `form_templates.flow` (jsonb): flow_id, version, status, published_at, errors.
  - `form_requests.via` ('link' | 'flow').
- **ממשק:**
  - בעורך התבנית: לשונית "WhatsApp Flow", עם יצירה, פרסום, תצוגה מקדימה (iframe של Meta) ותוויות קצרות.
  - בשליחה: בחירה בין קישור ל-Flow.

### 5. אבטחה, פרטיות, משפט
- **זיהוי:** התשובה מגיעה ב-webhook חתום (HMAC, קיים), מהמספר שהטופס נשלח אליו.
  - תשובה ממספר אחר נדחית.
  - הטוקן חד-פעמי, אקראי, עם תוקף כמו היום.
- **אימות שרת מלא:** לכל ערך ולכל שדה חובה. אין סמיכות על הבדיקה בצד ווצאפ.
- **המידע עובר דרך Meta:** כבר במפת המידע, כספק של הערוץ הרשמי. יש לציין "טפסים" במדיניות הפרטיות.
- **⚠️ תוקף משפטי של חתימה מוקלדת ואישור מפורש לעומת חתימה מצוירת: דורש בדיקה משפטית.**
  - חוק חתימה אלקטרונית, התשס"א-2001: חתימה "אלקטרונית" פשוטה תקפה ככלל, אבל טפסים מסוימים עשויים לדרוש יותר.
  - האפשרות להמשיך עם קישור וחתימה מצוירת נשמרת לכל טופס.
- **נגישות:** ווצאפ אחראית על המסכים. אצלנו: תוויות ברורות, טקסט עזר, הודעות שגיאה מובנות, ושמירה על הקישור כחלופה.

### 6. שלבי עבודה
| שלב | תוכן |
|---|---|
| W1 | ממיר Flow JSON ותוויות קצרות, עם בדיקות יחידה. כולל בדיקה מול כללי Meta: 20 תווים, ענפים |
| W2 | Flows API באדפטר: יצירה, עדכון, פרסום, ביטול, סטטוס ושגיאות. לשונית בעורך |
| W3 | שליחה מהשיחה וקליטת `nfm_reply` ← PDF חתום ועמוד ביקורת |
| W4 | שליחה קבוצתית דרך תבנית עם כפתור Flow (אחרי אישור תבנית ב-Meta) |
| W5 | בדיקה על מכשיר אמיתי (עברית ו-RTL, אנדרואיד ואייפון), e2e ו-axe, תיעוד |

## חלק ב: ערוץ SMS

### 1. מטרה (לבחירתכם, ראו שאלה 3)
- **(א) גיבוי לקוד האימות בטפסים:** למי שאין ווצאפ, או כשהערוץ נפל.
- **(ב) תזכורות לטפסים ולשליחה קבוצתית:** למי שאין ווצאפ.
- **(ג) ערוץ שיחה דו-כיווני מלא בתיבה:** הודעה נכנסת ← שיחה ← בוט ונציג.

### 2. ארכיטקטורה
- **אדפטר `channels/sms.ts`** עם ממשק ספק אחיד: `send(to, text)`, קליטת webhook נכנס, ודוח מסירה.
- **ספקים:**
  - **Twilio:** תיעוד ציבורי. webhook חתום ב-`X-Twilio-Signature`. **דורש אימות** של זמינות שם שולח (Alphanumeric) בישראל ושל המחיר.
  - **ספק ישראלי (019 / InforU / אחר):** לפי מה שיש לכם חוזה איתו. ה-API שלהם **דורש אימות** מול התיעוד שתקבלו מהם.
- **עלות ובטיחות:**
  - מונה תווים בעברית (UCS-2: 70 לחלק, 67 בהודעה מפוצלת).
  - מגבלת הוצאה יומית וחודשית.
  - "הסר" / STOP נאכף.
  - אין שליחה יזומה שיווקית (שלב F נדחה).
- **סודות:** פרטי ההתחברות לספק מוצפנים (כמו בערוצים הקיימים), ואפשר רק לכתוב אותם, לא לקרוא.

### 3. שלבי עבודה
| שלב | תוכן |
|---|---|
| S1 | אדפטר וספק ראשון, הגדרות, שליחת ניסיון, מגבלות עלות |
| S2 | קוד אימות לטפסים ב-SMS (אם נבחר א') |
| S3 | ערוץ דו-כיווני בתיבה, webhook חתום, דוח מסירה (אם נבחר ג') |

## שאלות לאישור
1. **חתימה ב-Flows:** האם אישור מפורש ושם מלא מוקלד מספיקים ליחידה? אם לא, לטפסים שדורשים חתימה מצוירת נשאיר את הקישור, ו-Flows ישמשו רק לטפסים בלי חתימה מצוירת.
2. **סדר עדיפויות:** להתחיל ב-Flows (ההמלצה שלי, כי הכול כבר מחובר: ערוץ רשמי, טפסים, webhook), או ב-SMS?
3. **SMS:** לאיזה שימוש: (א) קוד אימות, (ב) תזכורות, (ג) ערוץ מלא? ועם איזה ספק יש לכם חוזה, או שנבחר?
4. **תקציב SMS:** מגבלת הוצאה חודשית לברירת מחדל?
