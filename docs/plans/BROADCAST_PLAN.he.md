## 1. מטרה
לשלוח ליחידת הבטיחות הודעה יזומה לקבוצת אנשים, דרך הערוץ הרשמי בלבד, עם תיעוד, הסרה ודוח. דוגמאות:
- התרעת בטיחות ("תרגיל פינוי מחר ב-10:00 בבניין 12").
- תזכורת להדרכה שנתית או לחידוש הסמכה.
- עדכון נוהל ("נוהל עבודה בגובה עודכן, ראו קישור").
- תזכורת למילוי טופס. היום זה קיים לטופס אחד. כאן זה יהיה כללי.

**מחוץ לתחום ה-MVP:**
- שיווק ופרסום.
- שליחה בווצאפ QR או בטלגרם. זה חסום בכוונה, בגלל סיכון חסימה והפרת תנאי השימוש.
- SMS (שלב G).
- תזמון חוזר, למשל "כל חודש" (אפשר בהמשך).

## 2. User Stories
1. כממונה בטיחות, אני בוחר קהל (תגיות, בניין או אזור אחריות, פקולטה, סטטוס, רשימה מאקסל), ורואה כמה אנשים יקבלו ההודעה ולמה אחרים לא (הוסרו, אין הסכמה, אין מספר).
2. אני בוחר תבנית מאושרת, ממלא את המשתנים (כולל {שם פרטי} לכל נמען), רואה תצוגה מקדימה, ושולח ניסיון לעצמי.
3. אני שולח מיד או מתזמן, ומנהל מאשר לפני שליחה מעל X נמענים (סף שנקבע בהגדרות).
4. אני רואה דוח חי: נשלח, נמסר, נקרא, נכשל (עם סיבה), הוסר. אפשר לייצא אותו.
5. נמען שעונה להודעה מקבל שיחה רגילה בתיבה: הבוט ובטי מטפלים, ואחר כך נציג.
6. נמען שכותב "הסר" לא יקבל עוד הודעות תפוצה. זה מתועד, ועדיין אפשר לענות לו אם הוא פונה בעצמו.
7. מנהל רואה ביומן הביקורת מי שלח מה, למי ומתי.

## 3. מסכים וזרימה
1. **"תפוצה" בתפריט.** מוצג רק למי שיש לו את ההרשאה החדשה `broadcast.send`. המסך מציג רשימת תפוצות לפי סטטוס: טיוטה, ממתין לאישור, מתוזמן, נשלח, בוטל.
2. **אשף בארבעה צעדים, נגיש למקלדת וקורא מסך:**
   - קהל, עם ספירה חיה ופירוט החרגות.
   - תבנית ומשתנים, עם תצוגה מקדימה ושליחת ניסיון.
   - זמן שליחה.
   - סיכום ואישור. מופיעה אזהרת עלות לפי מונה ההודעות החודשי.
3. **מסך דוח לתפוצה:** טבלה רספונסיבית, סינון לפי מצב, וייצוא CSV.
4. **בכרטיס איש קשר:** מצב הסכמה, כלומר מקור ותאריך, ו"הוסר מתפוצה".

## 4. ארכיטקטורה
- **שירות `broadcast/`:**
  - בניית קהל: שאילתות על contacts, profile, tags ו-areas.
  - יצירת נמענים.
  - שליחה מדורגת דרך `ChannelManager.sendTemplate`, בבקר הקצב הקיים, עם חלוקה למנות ועצירה אוטומטית כשמונה ההודעות החודשי מגיע למגבלה.
  - עדכון מצבי מסירה מ-statuses ב-webhook: sent, delivered, read, failed.
- **ריצה ברקע:** ה-tick הקיים כל דקה, כמו `sendDueScheduled`. התור נשמר ב-DB, ולכן אתחול של השרת לא מאבד אותו ולא שולח פעמיים: לכל נמען יש "claim" לפני שליחה.
- **מקור אמת להסכמה ולהסרה:** טבלת `consents`. הסרה דרך "הסר" נאכפת בכל תפוצה.

## 5. סכמת נתונים (מוצע)
- `broadcasts`:
  - id, title, channel_id, template (name, lang, params), audience (jsonb: הקריטריונים)
  - status: draft / pending_approval / scheduled / sending / done / cancelled
  - scheduled_at, created_by, approved_by, approved_at
  - counters
- `broadcast_recipients`:
  - broadcast_id, contact_id, status: queued / sent / delivered / read / failed / skipped
  - error, external_message_id, sent_at
  - UNIQUE (broadcast_id, contact_id)
- `consents`:
  - contact_id, kind ('broadcast'), granted_at, source ('form' | 'import' | 'chat' | 'manual'), wording, revoked_at, revoked_source

## 6. API (כל הנתיבים דורשים התחברות והרשאה)
| נתיב | מה עושה |
|---|---|
| `GET /broadcasts` | רשימת תפוצות |
| `POST /broadcasts` | יצירת טיוטה |
| `PUT /broadcasts/:id` | עריכת טיוטה |
| `POST /broadcasts/:id/audience-preview` | ספירה ופירוט החרגות. שמות מוצגים רק למי שמורשה לראות אנשי קשר |
| `POST /broadcasts/:id/test` | שליחת ניסיון למספר של השולח |
| `POST /broadcasts/:id/submit` | שליחה, או העברה לאישור מעל הסף |
| `POST /broadcasts/:id/approve` | אישור (`broadcast.approve`). אסור לאשר תפוצה שאתה יצרת |
| `POST /broadcasts/:id/cancel` | ביטול. עוצר גם שליחה באמצע |
| `GET /broadcasts/:id/report` | דוח |
| `GET /broadcasts/:id/report.csv` | ייצוא הדוח |
| `GET /consents`, `PUT /contacts/:id/consent` | ניהול הסכמה |

## 7. החלטות טכנולוגיות
- **ערוץ רשמי ותבניות בלבד.** מחוץ לחלון 24 השעות Meta מאפשרת רק תבניות מאושרות.
  - קטגוריית "Utility" מתאימה לעדכונים תפעוליים, ו-"Marketing" לשיווק.
  - הסיווג בפועל נקבע על ידי Meta ויכול להשפיע על המחיר. **דורש אימות מול התיעוד הרשמי.**
  - **חלופה:** הודעה חופשית רק למי שכתב ב-24 השעות האחרונות. זה מוגבל מאוד, ולכן לא מספיק כפתרון.
- **בלי ספריית תורים חיצונית (Redis/BullMQ).** התור ב-PostgreSQL פשוט יותר לתחזוקה ולגיבוי, ומספיק להיקפים של אלפים.

## 8. אבטחה, פרטיות ונגישות
- **Threat model:**
  - **הנכס:** רשימות טלפונים, ויכולת לשלוח בשם היחידה.
  - **איומים:**
    - שולח לא מורשה.
    - הסלמת הרשאות.
    - דליפת רשימות בייצוא.
    - הצפה ועלות.
    - הזרקה במשתנים.
  - **בקרות:**
    - הרשאות נפרדות `broadcast.send` ו-`broadcast.approve`.
    - אישור על ידי אדם נוסף מעל סף.
    - מגבלת קצב ומגבלה חודשית.
    - משתנים כטקסט בלבד, באורך מוגבל.
    - יומן ביקורת.
    - ייצוא דוח רק למורשים.
- **פרטיות:**
  - מינימום מידע: הדוח מציג סטטוס, לא תוכן תשובות.
  - נמענים שהוסרו לא נמחקים מהתיעוד, כדי שנוכל להוכיח הסרה.
  - Retention לדוחות: לפי מדיניות ההודעות.
  - Meta כמעבד מידע: כבר במפת המידע.
- **חוק:**
  - הודעה פרסומית כפופה לסעיף 30א לחוק התקשורת: הסכמה מראש, סימון "פרסומת", דרך הסרה.
  - הודעות תפעוליות לעובדים, כמו התרעת בטיחות, הן כנראה לא "דבר פרסומת", אבל **דורש בדיקה משפטית**. כך גם השאלה אם לעובדים נדרשת הסכמה נפרדת. ראו גם תיקון 13 לחוק הגנת הפרטיות.
- **נגישות:**
  - אשף עם כותרות וסדר פוקוס נכון.
  - הודעות שגיאה מקושרות לשדות.
  - טבלאות רספונסיביות.
  - הודעות סטטוס עם `role=status`.
  - בדיקת axe בכל צעד.
