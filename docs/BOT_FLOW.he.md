# תרשים זרימה לבוט

בונים שיחה עם הלקוח כתרשים במקום תפריט ממוספר בלבד. מגיעים אליו מהתפריט **תרשים זרימה**.

## צמתים
| צומת | מה עושה |
|------|---------|
| הודעה | שולחת טקסט וממשיכה |
| תפריט | מציג אפשרויות וממתין. הלקוח יכול לבחור במספר, בשם, **או לכתוב חופשי**: "אני צריך משהו עם פיגומים" יתאים לאפשרות "בטיחות בגובה" |
| שאלה (איסוף פרט) | שואלת שם / טלפון / אימייל / טקסט, בודקת תקינות, ושומרת. התשובות נרשמות כהערה פנימית בשיחה, ושם משמש כשם איש הקשר |
| תנאי | מסתעף לפי שעות הפעילות, הערוץ (ווצאפ/ווצאפ רשמי/טלגרם) או פרט שנאסף |
| מאגר ידע | עונה ממאגר הידע. יש ענף "נמצא" וענף "לא נמצא" |
| הפניה לווצאפ אישי | הודעה עם קישור צ'אט ישיר לאיש מקצוע |
| תגית | מוסיפה תגית לשיחה |
| העברה לנציג | מעבירה לנציג מסוים (או להקצאה הרגילה). אחרי זה הבוט שותק |
| סיום | הודעת סיום. אם הלקוח כותב שוב אחרי חצי שעה, התרשים מתחיל מחדש |

## עבודה עם העורך
- **יצירה מהתפריט הממוספר הקיים**: נקודת פתיחה מוכנה (כולל הפניות והעברות לנציג שהגדרתם).
- התרשים מצויר אוטומטית. לחיצה או Enter על צומת פותחת אותו לעריכה בטופס, אפשר לערוך הכול גם בלי עכבר.
- **בדיקה בשיחה**: מדמה לקוח מול התרשים (גם בלי לשמור), כולל שעות סגורות וערוץ, ומראה גם את הפעולות שהיו קורות (תגית, הערה, העברה).
- שמירה בודקת: צומת התחלה קיים, אין צומת שמצביע על צומת שנמחק, ואין מעגל של צמתים שלא ממתינים ללקוח.
- **הפעלה**: "הפעלת התרשים כמצב הבוט". אפשר לחזור לתפריט הממוספר בכל רגע. הבוט עצמו נדלק ב"בוט".

## כללים שתמיד חלים
- מילת "נציג" (והמילים שהוגדרו בבוט) מעבירה לנציג מכל מקום. "תפריט" מתחיל מחדש. קובץ או תמונה מועברים לנציג.
- הודעה לא מובנת בתפריט: מנסים קודם מאגר ידע, ואז מציגים שוב את התפריט, ואחרי הניסיונות שהוגדרו מעבירים לנציג.
- הגנה מלולאות: מגבלה על כמות ההודעות האוטומטיות בזמן קצר, ועל כמות הצמתים שרצים בהודעה אחת.

## מגבלות
- עד 60 צמתים. עד 9 אפשרויות בתפריט.
- אין עדיין הרצה בזמן (המתנה/תזכורות) ואין משתנים חופשיים מעבר לארבעת הפרטים.
- ההבנה בניסוח חופשי מדויקת יותר עם חיפוש משמעות (ראו מאגר ידע). בלי המודל היא מתבססת על מילות האפשרות והניסוחים הנוספים שהוגדרו.
