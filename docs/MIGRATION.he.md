# גיבוי מלא והעברה לשרת חדש

## גיבוי מלא
- **מה נכלל:** מסד הנתונים (הודעות, אנשי קשר, משתמשים, הגדרות, מאגר ידע, תרשימים, חיבורי ערוצים כולל סשן הווצאפ, מפתחות התראות) **וכל הקבצים המצורפים**.
- **הצפנה:** AES-256-GCM במפתח שנגזר מ-`ENCRYPTION_KEY` של השרת. בלי המפתח הקובץ חסר תועלת, ולכן **שמרו את קובץ `.env` (או לפחות `ENCRYPTION_KEY`) במקום בטוח, בנפרד מהגיבויים**.
- **איך:** הגדרות ← גיבויים ← "גיבוי מלא עכשיו". "בדיקת תקינות" מוודאת שהקובץ נפתח, שהמסד שלם וכמה קבצים מצורפים בו.
- **אוטומטי:** `BACKUP_AUTO_HOUR=3` ב-`.env` יוצר גיבוי מלא כל לילה (ב-3:00) ובודק אותו. `BACKUP_KEEP` קובע כמה לשמור (ברירת מחדל 14).
- **עותק מחוץ לשרת (מומלץ):** הורידו גיבוי מהפאנל, או העתיקו מה-volume `backups`, לאחסון נפרד (מחשב, ענן). גיבוי שנמצא רק על אותו שרת לא מגן מתקלה בשרת.

## העברה לשרת חדש (3 שלבים)
**1. בשרת הישן:**
```bash
cd /opt/botwa && sudo ./scripts/migrate-export.sh
```
בוחרים סיסמה (12 תווים לפחות). נוצר קובץ `botwa-migration-....bundle` אחד שמכיל את המסד, הקבצים וקובץ ההגדרות. הוא מוצפן בסיסמה, ולא במפתח של השרת, כי השרת החדש עוד לא מכיר אותו.

**2. העתקה לשרת החדש:**
```bash
scp /opt/botwa/botwa-migration-*.bundle root@NEW-SERVER:/root/
```

**3. בשרת החדש:** מתקינים Botwa כרגיל (פקודת ה-bootstrap, בלי ליצור מנהל), מוודאים שהוא עולה, ואז:
```bash
cd /opt/botwa && sudo ./scripts/migrate-import.sh /root/botwa-migration-....bundle
```
מקלידים `MOVE` ואת הסיסמה. הסקריפט:
- פותח ובודק את הקובץ (סיסמה שגויה או קובץ פגום נעצרים לפני שינוי כלשהו),
- בונה `.env` חדש: כל ההגדרות והסודות מהשרת הישן, חוץ מכתובת הדומיין, הגדרות ה-proxy וסיסמת מסד הנתונים של השרת החדש (הקובץ הקודם נשמר כ-`.env.before-migration-...`),
- עוצר את האפליקציה, מחליף את המסד והקבצים, ומפעיל מחדש. מיגרציות לגרסה חדשה יותר רצות אוטומטית.

אחרי ההעברה:
- **ווצאפ בחיבור QR:** מספר יכול להיות פעיל בשרת אחד בלבד. עוצרים את השרת הישן (`docker compose stop`) לפני בדיקה. אם הסשן לא עולה, מחברים מחדש ב-QR מעמוד הערוצים.
- **דומיין:** מעדכנים DNS לכתובת השרת החדש (או מגדירים דומיין חדש ב-`.env`).
- **ניקיון:** מוחקים את קובץ ה-`.bundle` משני השרתים ואת `.env.before-migration-*` כשהכול עובד. הקובץ מכיל את כל המידע של המערכת.

## אבטחה
- הסיסמה עוברת דרך משתנה סביבה ולא בשורת הפקודה (לא נראית ברשימת התהליכים).
- הקובץ מוצפן ב-AES-256-GCM עם מפתח שנגזר מהסיסמה ב-scrypt. כל שינוי בקובץ מתגלה.
- בפתיחה מתקבלים רק קבצים צפויים (מסד, הגדרות, תיקיית קבצים), בלי נתיבים חריגים או קישורים.
- ההעברה עצמה (scp) מוצפנת. לא מעבירים את הקובץ במייל או בצ'אט.

**נבדק אוטומטית:** יצירה, פתיחה, סיסמה שגויה, זיהוי שינוי בקובץ, מיזוג ההגדרות ושחזור מסד וקבצים. **לא נבדק:** הרצת הסקריפטים מקצה לקצה על שני שרתים אמיתיים עם docker compose. מומלץ לבצע חזרה (העברה לשרת בדיקה) לפני מעבר אמיתי.
